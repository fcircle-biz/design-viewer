# 顧客管理システム（CRM） 仕様書

> 状態: 設計中（未実装）。本書は Salesforce Sales Cloud / Service Cloud に類似した機能範囲を、中堅 B2B 企業向けに絞り込んだ独自の設計である。

## 1. 概要

見込み客（リード）の獲得から、商談・受注、受注後の問い合わせ対応（ケース）までを 1 つのシステムで管理する B2B 向け顧客管理システム。
営業担当が顧客情報と活動履歴を記録し、営業マネージャーがパイプラインと売上見込みをレポートで把握できるようにする。

### 1.1 対象ユーザー

| ロール | 説明 | 権限 |
| --- | --- | --- |
| 営業担当 | リード・取引先・商談を担当する | 自分が所有するレコードの参照／作成／更新。同じチームのレコードは参照のみ |
| 営業マネージャー | チームの営業担当を管理する | 配下チームの全レコードの参照／更新、所有者の変更、値引率 20% 超の見積の承認 |
| サポート担当 | 顧客からの問い合わせ（ケース）に対応する | ケースの参照／作成／更新、取引先・取引先責任者の参照 |
| システム管理者 | システム全体を管理する | 全機能、ユーザー・ロール管理、データインポート |

### 1.2 対象外

- 請求・入金管理（会計システム側で行う）
- メール配信（マーケティングオートメーション）
- モバイルアプリ（ブラウザのみ対応）
- 複数通貨（日本円のみ）

### 1.3 外部連携

| 連携先 | 方向 | 内容 |
| --- | --- | --- |
| Web 問い合わせフォーム（自社サイト） | 入力 | フォーム送信内容をリードとして自動登録する |
| メールサーバー（SMTP） | 出力 | 担当割り当て・承認依頼・ケース更新の通知メールを送る |
| 会計システム | 出力 | 受注した商談の受注データを CSV で日次出力する |
| CSV ファイル | 入力 | 取引先・取引先責任者・リードを一括取り込みする |

## 4. 業務ルール

### 4.1 リード

- 状況は「新規 → 対応中 → 評価済み」または「不適格」。不適格にするときは理由（予算なし／時期未定／競合決定／重複／その他）を必須とする。
- Web 問い合わせフォームから登録されたリードは、リードソース「Web」、状況「新規」で作成し、担当地域（都道府県）に応じた割り当てルールで所有者を決める。該当するルールが無ければ「未割り当て」キューに入る。
- メールアドレスが既存のリード・取引先責任者と一致する場合は、重複の候補として詳細画面に警告を表示する（登録は止めない）。
- 取引開始できるのは状況「評価済み」のリードのみ。取引開始したリードは読み取り専用になり、作成した取引先・取引先責任者・商談へのリンクを持つ。

### 4.2 取引先・取引先責任者

- 取引先名は必須。法人番号（13 桁）は任意だが、入力した場合は重複不可。
- 取引先は親取引先を 1 つ持てる（グループ会社の階層）。
- 取引先責任者は必ず 1 つの取引先に属する。

### 4.3 商談

- フェーズと確度（%）の既定値: 見込み 10% → 要件確認 25% → 提案 50% → 見積提示 75% → 交渉 90% → 受注 100% ／ 失注 0%。確度は手動で変更できる。
- 失注にするときは失注理由（価格／機能／競合／時期／その他）と競合先を必須とする。
- 受注・失注にした商談は、営業マネージャー以上でなければフェーズを戻せない。
- 金額は商品明細の合計。明細が無い場合は手入力できる。
- 完了予定日を過ぎても受注・失注になっていない商談は、ホーム・パイプラインで赤く強調する。

### 4.4 見積

- 見積番号は「Q-年-連番 5 桁」で自動採番する（例: Q-2026-00042）。
- 明細ごとの値引率が 20% を超える見積は、営業マネージャーの承認が必要。承認されるまで PDF 出力できない。
- 1 つの商談で「同期中」にできる見積は 1 つ。同期中の見積の明細が商談の商品明細・金額に反映される。
- 有効期限の既定値は発行日から 30 日。

### 4.5 活動

- ToDo は件名・期日・関連先（リード／取引先／取引先責任者／商談／ケースのいずれか）が必須。
- 行動（予定）は開始・終了日時が必須。終了は開始より後であること。
- 完了した活動は、関連先の詳細画面の活動タイムラインに新しい順で表示する。

### 4.6 ケース

- 受付チャネル: 電話／メール／Web。状況: 新規 → 対応中 → 回答待ち → 解決 → クローズ。
- 優先度ごとの初回応答 SLA: 高 4 時間、中 1 営業日、低 3 営業日。SLA を超過したケースは一覧で赤く強調し、担当者と営業マネージャーに通知メールを送る。
- エスカレーションすると優先度を「高」にし、エスカレーション先のキューへ所有者を変更する。
- 解決から 7 日間顧客の返信が無い場合、夜間バッチで自動的にクローズする。

### 4.7 受注データ出力

- 前日にフェーズが「受注」になった商談を、取引先コード・商談名・受注日・金額・明細とともに CSV 出力する。
- 出力済みの商談には出力日時を記録し、再出力しない。

## 6. 非機能要件

- 対応ブラウザ: Chrome／Edge の最新版。
- 一覧画面の表示は 10 万件のデータで 2 秒以内。
- すべてのレコードの作成・更新・削除について、変更前後の値・変更者・日時を監査ログに保存し、5 年間保持する。

## 7. システム構成（AWS）

本システムは AWS 上で稼働させる。可用性を確保するため、2 つのアベイラビリティゾーンに分けて配置する。

| 区分 | 内容 |
| --- | --- |
| リージョン・ゾーン | 東京リージョン（ap-northeast-1）の 2 つのアベイラビリティゾーン（a／c）を使う |
| ネットワーク | VPC 1 つ（10.0.0.0/16）。各ゾーンにパブリックサブネット（10.0.1.0/24、10.0.2.0/24）とプライベートサブネット（10.0.11.0/24、10.0.12.0/24）を置く |
| 公開・防御 | 利用者のブラウザからの HTTPS はロードバランサー（ALB）で受ける。ALB の前段に AWS WAF を置く |
| アプリケーション | Amazon ECS on AWS Fargate。プライベートサブネットで 2 ゾーンにタスクを分散する |
| データベース | Amazon RDS for PostgreSQL。プライマリをゾーン a、スタンバイをゾーン c に置く Multi-AZ 配置とする |
| ファイル | CSV インポートのファイル、受注データ出力の CSV、監査ログのアーカイブは Amazon S3 に保存する |
| バッチ | 夜間バッチ（受注データ出力・ケース自動クローズ）は Amazon EventBridge Scheduler が ECS タスクを起動する |
| 通知メール | 通知メールは Amazon SES から送る |
| 外向き通信 | プライベートサブネットから外部への通信は、各ゾーンの NAT ゲートウェイを経由する |
| 監視 | アプリケーション・バッチのログとメトリクスは Amazon CloudWatch に集約する |

外部との接続:

- Web 問い合わせフォーム（自社サイト）からのリード登録は、ALB 経由の API で受ける。
- 会計システム向けの受注データ CSV は S3 に置き、会計システム側が取得する。
